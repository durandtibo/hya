    Migrate from 0.4 to 0.5¶

    hya 0.5 has breaking changes. This page lists them, with the change to make in your code.

    Requirements¶

    hya 0.5 requires omegaconf>=2.4,<3.0 (it was >=2.2,<3.0). The code uses OmegaConf.register_resolver and has no compatibility layer for older versions.

    !!! warning

    The releases `hydra-core` 1.3.1 and 1.3.2 declare `omegaconf>=2.2,<2.4`, so a package
installer (`pip`, `uv`) cannot install them together with `hya` 0.5. Only `hydra-core` 1.3.0
does not cap OmegaConf. Use a release of Hydra that accepts OmegaConf 2.4 when it is
available.

    Summary of the changes¶

    Change Before (0.4) After (0.5)
    hya.add does not modify its arguments conf.x changed when read through ${hya.add:${x},[3]} conf.x is unchanged
    hya.mul on a config list and an int TypeError TypeError (numbers only), documented
    register_resolvers(*, replace=False) an existing key is skipped silently an existing key is skipped with a warning; replace=True replaces
    register(key, *, exist_ok=False) exist_ok can be positional exist_ok is keyword-only
    registry.state the live dict a read-only mapping
    hya.to_path URL parsed for every input removed: use hya.path (decodes file: URLs only)
    hya.braceexpand a generator a list[str]
    hya.torch.dtype error an unordered set of dtypes the sorted dtype names
    import hya about 0.6 s, imports torch and numpy, emits warnings no import of numpy, torch and braceexpand, no warning
    hya.sub, hya.sqrt, hya.max, ... errors the error of the hya wrapper the error of the standard library
    OmegaConf requirement >=2.2,<3.0 >=2.4,<3.0

    Removed API¶

    Removed Use instead
    hya.resolvers.{asinh,exp,floordiv,len,log,log10,max,min,neg,pow,sinh,sqrt,sub,truediv}_resolver the standard library callable (math.exp, ...)
    hya.resolvers.to_path_resolver and the key hya.to_path hya.path
    hya.torch.get_dtypes dir(torch) and isinstance(..., torch.dtype)

    New API: ResolverRegistry.register_lazy, register_resolvers(*, replace=False), and from hya import ResolverRegistry.

    Changes to make¶

    Overriding a resolver¶

    from hya import get_default_registry

registry = get_default_registry()


@registry.register("hya.add", exist_ok=True)
def custom_add(first, *others): ...


# 0.4: silently ignored. 0.5: warns and keeps the old resolver, unless replace=True
registry.register_resolvers(replace=True)

    hya.to_path¶

    # 0.4
local_file: ${hya.to_path:file:///data/file.txt}

# 0.5
local_file: ${hya.path:file:///data/file.txt}

    A path that is not a file: URL is not decoded anymore: ${hya.path:/data/a%20b} keeps the %20.

    hya.braceexpand¶

    The result is a list, so it can be read several times, indexed and dumped. The pattern must be quoted in an interpolation:

    files: ${hya.braceexpand:"file_{1..5}.txt"}

    hya.mul with a list¶

    ${hya.mul:${x},2} with x: [1, 2] is not supported: repeat the list in your code.

    Tilde in hya.path¶

    A path with a tilde must be quoted in an interpolation: ${hya.path:"~/data"}.
